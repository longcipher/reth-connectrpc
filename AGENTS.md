# reth-connectrpc Agent Instructions

## Non-negotiables

- Surgical edits only: every changed line must trace to the request. No drive-by refactors, no reformatting untouched code, no deleting pre-existing dead code (mention it instead).
- Fix root causes. Never silence a warning, weaken a check, or patch a symptom to make a gate pass.
- Never report completion while any `just` gate below fails. Report the failure verbatim and stop.
- Stop and ask when a request is ambiguous, conflicts with existing conventions, or requires credentials, publishing, or destructive operations.
- When a correction reveals a missing rule, add one specific rule here ("always X for Y", never "be careful with Y"); delete rules that never catch real errors.

## Scope

- Workspace members are the six crates under `crates/`; there is no `bin/` member. `README.md` is still the old template text and does not describe this project.
- `base-common-consensus` holds Base-layer alloy consensus types (receipts, EIP-8130 transactions, extra-data encoders, predeploys); `tempo-primitives` holds Tempo primitive types; `tempo-contracts` holds the Tempo precompile bindings; `tempo-hardfork` holds hardfork ids and activation schedules.
- `base-rpc` and `tempo-rpc` are the two ConnectRPC servers; each owns a `proto/*.proto` file, a `build.rs` and a `src/codec/` translation layer.
- The RPC stack is `connectrpc` (Tower-based ConnectRPC) with `buffa` as the protobuf runtime, generated by `connectrpc-build` and pulled in with `connectrpc::include_generated!()`. `prost`/`tonic` appear in `Cargo.lock` only as transitive dependencies of `reth` — do not import them directly.
- Building the RPC crates needs `protoc` (`protobuf-compiler`); CI installs it. English only in code, comments, docs, and commit messages.

## Execution

- Parallelize aggressively: dispatch subagents for independent research, exploration, and implementation.
- NEVER run two `cargo` commands concurrently, and never overlap file edits with a running `cargo` command (`target/` file lock): finish edits, wait, then run.
- NEVER use `git worktree`. Edit the current branch in place.
- TDD for behavior changes: failing test first, smallest change to pass, then run `just test` again and fix the failures it exposes.

## Verification loop

After each feature or bug fix, in order; any failure means the task is not done:

```bash
just format
just lint
just test
```

`just lint` is the CI gate: `typos`, `rumdl`, `cargo sort --check`, `cargo +nightly fmt --check`, `cargo +nightly clippy -D warnings`, `cargo machete`. `just ci` adds `test-all` and `build`.

## Rust workspace rules

- Edition 2021, resolver 2. Workspace lints live in the root `Cargo.toml`; members opt in with `[lints] workspace = true`.
- `unwrap_used`, `expect_used`, `panic`, `todo`, `unimplemented`, `dbg_macro`, `print_stdout` and `print_stderr` are `deny`. `allow_attributes` is only `allow` here, so `#[allow(...)]` is legal but `#[expect(lint, reason = "...")]` is still preferred.
- `base-rpc` and `tempo-rpc` deliberately opt out with `[lints.clippy] pedantic = "allow" all = "allow"`; the other four crates run the full workspace lint table.
- The `reth` crates are pinned to the git revision `1bf2384`, and `[patch.crates-io]` re-pins `reth-codecs`, `reth-codecs-derive` and `reth-primitives-traits` to `reth-core` tag `v0.5.2`. Keep those pins in sync when bumping reth.
- `base-common-consensus` exposes `std`, `k256`, `serde`, `serde-bincode-compat`, `arbitrary` and `reth`; `tempo-primitives` exposes `std`, `reth`, `reth-codec`, `serde` and `arbitrary`; `tempo-contracts` and `tempo-hardfork` expose `std` and `serde`. Feature-gate new code, do not make features unconditional.
- There is no `rust-toolchain.toml`: CI installs nightly, so use `cargo +nightly fmt` and `cargo +nightly clippy` exactly as the Justfile does.
- `.cargo/config.toml` sets `rustc-wrapper = "sccache"`; clippy invocations must clear it (`RUSTC_WRAPPER=`) exactly as the Justfile does.
- Never hand-type dependency versions. Shared crates go into root `[workspace.dependencies]` and members reference them with `workspace = true`.

## Dependency choices

- Consensus and encoding come from `alloy-*` and `reth-*`; do not add a second consensus stack.
- Protobuf/gRPC work goes through `connectrpc` and `buffa`; never add `tonic` or `prost` as direct dependencies.
- Async runtime is `tokio` with `full`; stream plumbing uses `futures-util` and `tokio-stream`.
- Errors: `thiserror` in the crates that define error enums. `eyre` is declared by `base-rpc` and `tempo-rpc` but unused — leave it or remove it deliberately, do not start using it.
- Forbidden here: `anyhow`, `log`, `reqwest`, `dashmap`.

## Code conventions

- Logging: `tracing` only. The RPC servers are the only place that logs.
- `unsafe` does not appear in this workspace; keep it that way and push raw FFI work into `reth`.
- Tests: `proptest` properties live in `tempo-primitives` (block timestamps, Tempo signatures), `rstest` cases in `base-common-consensus`; both run in the ordinary `cargo test` loop.
- The protobuf payloads in `src/codec/block.rs` are the boundary between chain types and the wire format: keep the `proto` message shapes and the codec in sync, and change the `.proto` file before the codec.
- The manifests still carry `[package.metadata.cargo-shear] ignored` lists, but CI installs `cargo machete`, which does not read them. Mirror those ignore lists into `[package.metadata.cargo-machete]` before trusting the unused-dependency gate.
